# PRO-228 — DS-2: Token pipeline — DTCG source, OKLCH, Utopia scales

Parent: PRO-226. Builds on PRO-227's scaffold (layer at root, playground via `extends`, pnpm, CI).

## Objective

Single design-token source in DTCG format, compiled by Style Dictionary into `@theme` CSS consumed by the layer: OKLCH palette + Utopia fluid type/space scales, semantic values seeded from Social House's current rendered look.

## Semantic seeds extracted from Social House

From `social-house-frontend/app/app.config.ts` + `app/assets/css/brand.css` + component CSS:

- **Font**: `'Satoshi', ui-sans-serif, system-ui, sans-serif` (weights 400/500/700 via Fontsource).
- **Colors**: Nuxt UI `primary: indigo`, `neutral: slate` — i.e. Tailwind's indigo/slate palettes (already OKLCH in Tailwind v4; we take those exact values into our DTCG source so the rendered look is unchanged and the source of truth moves into `tokens/`).
- **Radius language**: Nuxt UI semantics (`--ui-radius`; Nuxt UI v4 default 0.25rem — the value the site actually renders with; the `0.5rem` in component CSS is only a fallback), pills at 9999px. We keep Tailwind-compatible radius steps and seed `--ui-radius: var(--radius-sm)` explicitly from tokens.
- **Shadow language**: subtle Tailwind-default-shaped shadows, black at low alpha — expressed as `oklch(0 0 0 / a)` (no hex, no rgb).

## Key decisions

1. **DTCG file layout** — `tokens/` at repo root:
   ```
   tokens/
   ├── color.tokens.json       # hand-authored: indigo + slate OKLCH scales (values lifted from Tailwind v4 theme.css)
   ├── font.tokens.json        # hand-authored: Satoshi font stack
   ├── radius.tokens.json      # hand-authored: radius scale + semantic ui.radius (reference)
   ├── shadow.tokens.json      # hand-authored: shadow scale, OKLCH colors
   ├── type.tokens.json        # GENERATED from utopia.config.json — Utopia type steps, clamp()
   ├── space.tokens.json       # GENERATED from utopia.config.json — Utopia space scale + one-up pairs, clamp()
   └── utopia.config.json      # Utopia parameters (single source for the two generated files)
   ```
   All `*.tokens.json` are DTCG (`$value`/`$type`/`$description`). The two Utopia files are regenerated by the build (committed, marked generated) so the repo always contains the complete DTCG set.

2. **Utopia computation**: `utopia-core` npm package, invoked inside `scripts/build-tokens.mjs` from the parameters in `tokens/utopia.config.json`. Pure math from fixed config → deterministic. Parameters: viewports 360→1240 (matches acceptance criteria), type base 16px→18px with ratio 1.2→1.25, steps −2…5; space multipliers 3xs(0.25) 2xs(0.5) xs(0.75) s(1) m(1.5) l(2) xl(3) 2xl(4) 3xl(6), plus Utopia one-up pairs.

3. **Style Dictionary v5** (ESM), one custom format, minimal transforms:
   - No color/dimension transforms — values are authored as final CSS (`oklch(...)`, `clamp(...)`, rem strings); SD provides DTCG parsing, tree flattening, and reference resolution.
   - Custom format `css/tailwind-theme` emits `app/assets/css/tokens.css`: a `@theme` block (token name = `--` + path joined with `-`, so JSON keys map 1:1 to Tailwind namespaces) plus a small `:root` block for tokens flagged `$extensions["ccm.scope"] = "root"` (Nuxt UI semantics like `--ui-radius`). References (`{radius.sm}`) are emitted as `var(--radius-sm)`.
   - Custom file header without timestamps → byte-identical output on every run.

4. **Tailwind v4 namespace mapping** (utilities coexist with the numeric scale):
   - `--text-step--2 … --text-step-5` → `text-step-0`, `text-step-3`, … (Utopia macro type rhythm; Tailwind's `text-sm`… remain untouched).
   - `--spacing-3xs … --spacing-3xl` (+ one-up pairs like `--spacing-s-m`) → `p-s`, `gap-m-l`, … Numeric spacing still derives from Tailwind's `--spacing: 0.25rem` multiplier → numeric = intra-component, Utopia = macro rhythm.
   - `--color-indigo-* / --color-slate-*` override Tailwind's palette with our (identical) OKLCH values — the source of truth becomes `tokens/`.
   - `--font-sans` → Satoshi stack; `--radius-*`, `--shadow-*` standard namespaces.
5. **Semantic aliasing primary/neutral**: via Nuxt UI's own mechanism — new layer-level `app/app.config.ts` with `ui.colors = { primary: 'indigo', neutral: 'slate' }`. We do NOT emit our own `--color-primary-*` (would collide with Nuxt UI's generated aliases).
6. **Wiring**: `app/assets/css/main.css` adds `@import "./tokens.css";` after `@import "@nuxt/ui";` — the `@theme` block is processed by the same Tailwind build the layer already ships.
7. **Font loading** stays an app concern (Social House loads Satoshi via Fontsource CDN): the layer ships the *stack token* only; the playground imports the Fontsource CSS itself so the docs page renders true.
8. **Determinism guard in CI**: after build, run `pnpm build:tokens` + `git diff --exit-code -- tokens app/assets/css/tokens.css` so a stale committed output fails the PR.

## Test strategy

- `pnpm build:tokens` twice → `diff` outputs byte-identical.
- Grep generated CSS for `#[0-9a-fA-F]` → zero raw hex.
- `pnpm lint`, `pnpm lint:style`, `pnpm build` green.
- Browser: playground `/tokens` page at 360px and 1240px — assert `--text-step-0`/`--spacing-m` resolve to different computed px at each viewport (fluid), swatches render.

## Risks

- SD color transforms mangling `oklch()` → avoided by using no value transforms (custom format passes raw values).
- `kebabCase` name transforms collapsing `step--2` → avoided by naming from `token.path.join('-')` directly.
- Overriding `--color-indigo-*` in `@theme`: identical values to Tailwind's, so zero visual delta; the override just relocates ownership.
- `@theme` inside an imported file: supported — same pattern `@nuxt/ui` itself uses; verified by the playground build + browser check.
